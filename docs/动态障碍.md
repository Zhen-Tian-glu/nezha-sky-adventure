# 阶段 3：动态障碍实现与验证

日期：2026-11-01；代码版本：0.5.0；构建编号：dynamic-obstacles-20261101-01。

> 本文保留阶段 3（0.5.0）记录；当前 0.6.0 已改为正式图片和 alpha 轮廓碰撞，五种动态升级为分层 VFX，见《正式素材接入.md》。旧实心矩形规则不代表当前图形。

## 当前交付

在阶段 2 的 8 类障碍、12 种场景内组合及无尽玩法基础上，接入五种临时矢量循环动画；保留三种静态障碍。正式手绘素材将在阶段 4 替换，本次不将临时图形记作正式美术完成。

| 类型 | 当前表现 | 基础周期 | 碰撞与轮廓 |
| --- | --- | --- | --- |
| 火球 | 橙金火焰形变、火芯起伏 | 1.2 秒 | 实心危险主体保持 |
| 水球 | 青蓝球体、三道流动波纹 | 1.8 秒 | 波纹限制在主体内 |
| 雷电 | 闪电符号与内光明暗变化 | 1.5 秒 | 暗相仍可见、仍有碰撞 |
| 风火轮 | 六片火焰轮辐旋转 | 2.4 秒 | 只旋转内部图案 |
| 海底妖怪 | 眨眼、眼神与嘴部微动、触须摆动 | 2.6 秒 | 不改变整体上下位置 |
| 山峰、石柱、乌云 | 各自静态识别图案 | 无 | 只随场景水平左移 |

当前实心色块和边框表示完整危险主体，内部图案用于区分类型及展示动态。不要将图案之外的色块当成安全区域。金色细线仍表示整组后缘，角色完整越过才加 1 分。

## 危险区域一致性

FlightModel 的碰撞、计分、水平速度与随机生成逻辑未修改。所有障碍都使用阶段 2 的稳定矩形危险包络；主体颜色始终不透明，边框始终可见。2 像素边框向内缩进半线宽，外缘与碰撞区域一致。

动画只改变包络内部的图形。图案最大半径 30 像素，横向预留至少 6 像素，纵向贴近通道的一侧向主体内部偏移 48 像素；包含圆形半径、折线厚度的实际图形范围均不得越出主体。不会有火苗、轮辐或触须突然伸进通道，也不会因透明帧产生看似可以穿越的空隙。

雷电只改变内部光圈及符号的亮度：符号 alpha 范围 210～254，实心主体始终为 255，循环约 0.67 Hz，不进行整块亮灭。雷电任何动画阶段都有相同碰撞。

## 生命周期与复用

动画取自 `FlightModel.elapsed`，不使用独立系统时钟、定时器或重复注册事件。按 20 FPS 量化，只对可见组重绘；池槽位带固定相位偏移，使同类障碍不完全同步。

- Ready：等待首次玩法点击，位置、时间和动画均冻结。
- Playing：水平移动、碰撞、计分和动画同步推进。
- Paused / GameOver：动画、位置及计分同时冻结。
- 恢复：从暂停时间继续，不补算后台时长，不重放点击。
- 重开：时间归零，绘制缓存失效，重新抽取主题和组合。

仍固定 4 个 ObstaclePair，各预建一个 InteriorMotion 子节点。回收和重开复用同一节点及 Graphics；静态配对只在生成变化时绘制，动态配对至多每 50 毫秒更新一次内部图形。这里没有承诺真机性能指标，设备帧率与内存另行测量。

## 代码与运行

正式项目：`nezha-sky-adventure-fresh`；入口场景：`assets/scenes/game.scene`。

- `assets/scripts/config/ObstacleConfig.ts`：各类型 motion / period 与 MOTION_RULES。
- `assets/scripts/gameplay/ObstacleMotion.ts`：无引擎依赖的动画图形采样。
- `assets/scripts/gameplay/ObstacleMotionRenderer.ts`：图形转换为 Cocos Graphics。
- `assets/scripts/gameplay/GrayboxGame.ts`：池内显示、时钟、可见性、缓存和冻结。
- `scripts/test-obstacle-motion.cjs`：动画变化、边界、周期、雷电及通行测试。
- `scripts/verify-obstacle-motion.cjs`：实际像素、生命周期、碰撞与布局检查。

在项目目录运行 `scripts/typecheck.ps1`、`scripts/test-graybox.ps1`。关闭本项目 Creator 实例后，分别运行 `scripts/build.ps1 -Platform web-mobile` 和 `scripts/build.ps1 -Platform wechatgame`。Web 服务运行后执行：

```powershell
node scripts/verify-obstacle-motion.cjs
node scripts/verify-obstacles.cjs
node scripts/verify-stage-2-input.cjs
```

后两项为原障碍和输入的回归入口，默认写入独立的 stage-3-obstacles-* / stage-3-input-* 证据；旧阶段证据保留。Playwright 和 Chrome 是浏览器自测依赖，脚本支持 PLAYWRIGHT_MODULE_PATH 与 GRAYBOX_URL。

试玩：http://127.0.0.1:8765/?stage=3 。服务未启动时，在项目目录执行 `python -m http.server 8765 --bind 127.0.0.1 --directory build/web-mobile`。点击开始后，再点击玩法区域起飞；障碍从右侧进入后可观察动画。
