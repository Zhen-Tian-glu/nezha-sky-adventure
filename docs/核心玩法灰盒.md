## 当前交付

已按用户确认的文档将长按飞行改为离散点按起飞。代码、操作提示、起飞视觉反馈、开始/重开和输入测试均已更新。没有加入阶段 2 的随机障碍池、计分或难度系统；正式角色动画和音效仍在后续阶段制作。

## 操作流程

1. 点击“开始试玩”或“重新开始”，进入空中待机；角色和障碍保持静止。
2. 再点击玩法区域，首次起飞并开始本局。每次新点击将竖直速度刷新为单次起飞速度；持续按住不会自动连发，松开不产生第二次起飞。
3. 停止点击后，角色在持续重力下减速、转为下落。连续点按控制高度；可在电脑使用鼠标单击或轻按空格，键盘自动重复会被忽略。
4. 点击玩法区域以外的界面不触发起飞。首根手指占有本次触摸，第二根手指不追加动力。
5. 触碰上下金线或灰色障碍结束本局；重开清空状态并重新等待首次点按。
6. 暂停或切后台后停止更新并清空待处理点击；点击“继续飞行”只恢复原有位置和速度，不起飞；下一次新点按才提供动力。

试玩地址：http://127.0.0.1:8765/?mode=tap 。若本地服务尚未启动，在项目目录运行 `python -m http.server 8765 --bind 127.0.0.1 --directory build/web-mobile`。

## 实现与调参

项目：nezha-sky-adventure-fresh；入口：assets/scenes/game.scene。

- FlightModel.requestFlap 收集单次命令，固定步消费后清空；同一步多个命令合并，不累计速度或排队自动连飞。
- FlightInput 只在玩法区域接受 TOUCH_START。区域本身及全局都处理松手/取消，适应 Cocos UI 消费事件的情况；松手只释放触摸所有权，取消清除未消费命令。
- 界面面板拦截点击，按键使用边沿触发；清除队列不会把仍按住的空格自动重复转换为新点击。
- GrayboxGame 显示“点击起飞”“点一下，开始飞行”等提示，短促金色线条作为灰盒扑动反馈；角色倾斜仍跟随速度。

| 参数 | 初值 | 说明 |
| --- | --- | --- |
| 单次起飞速度 | 360 设计像素/秒 | 刷新速度，不叠加 |
| 重力 | 1200 设计像素/秒² | 一直生效 |
| 上升 / 下落速度上限 | 360 / 440 | 下落方向为负 |
| 角色半径 | 28 | 只计算圆形主体，装饰不碰撞 |
| 上 / 下边界 | 480 / -500 | 固定玩法区域 |
| 障碍速度 / 宽度 | 170 / 80 | 固定三组循环 |
| 通道高度 / 间距 | 340 / 470 | 通过点击版固定通道可达性检查 |
| 固定步长 / 最大补时 | 1/120 秒 / 0.05 秒 | 不补算后台时间 |
| 倾斜范围 | -32°～22° | 只影响表现 |

这些是新点击版的灰盒初值，是否合适仍需用户试玩确认。

## 验证结果

- strict/noEmit 类型检查通过。
- 16 项独立模型测试通过：Ready 静止、首次点击、持续重力、下落时再次起飞、同一步合并、快速点按限速、下落限速、上下边界、两侧障碍、可通行中间区域、重开清理、暂停无回放、取消输入、无效时间，以及按离散点击策略持续飞行 30 秒。
- 11 组 Chrome 交互检查通过：开始按钮不穿透、待机冻结、鼠标按下/长按/松手/再次点击、速度与倾斜、下边界与失败冻结、重开、界面区域隔离、空格重复过滤、暂停/继续、引擎隐藏/显示模拟、连续点按触顶、实际飞入障碍，以及 390×844 模拟触摸与教学文案。
- 750×1334 与 390×844 截图已检查；Web Mobile、微信小游戏均构建成功。
- 微信开发者工具加载、微信真机及真实前后台切换仍未验证。引擎事件和浏览器模拟触摸不能代替手机实测；不编造用户手感或重玩意愿结论。

浏览器提示：favicon.ico 请求 404；CDP 模拟不可取消 touchcancel 时，Cocos 的 preventDefault 调用可能触发 Chrome 提示。触摸取消行为检查通过，两者作为非阻断提示记录，没有排除其他场景或脚本错误。
